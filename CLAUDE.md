# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Igra Na Klik** — a self-hosted AirConsole-style party game platform. One device is the "host" (TV/big screen), players join from their phones as "controllers" via a room code or QR. Real-time over Socket.io. 19 mini-games (plus a `test-game` dev module that is registered server-side but deliberately absent from `GAME_DEFINITIONS`), all content and in-game text in Serbian (Latin) by design.

## Commands

npm workspaces, all run from the repo root:

```bash
npm install                 # once
npm run build:shared        # REQUIRED before dev/build — others import @igra/shared's dist/
npm run dev                 # build:shared, then server + host + controller concurrently
npm run dev:server          # tsx watch
npm run dev:host            # Vite :5173
npm run dev:controller      # Vite :5174
npm run build               # production build of all 4 packages
```

Dev URLs: landing `localhost:3001/`, host `:3001/host/` (or `:5173/host/`), controller `:3001/play/` (or `:5174/play/`), admin `:3001/admin`.

**No test runner and no linter are configured.** "Testing" means `npm run dev` plus exercising the flow in two browser tabs (host + controller). There is no single-test command; if you add a harness, document its invocation here.

`npm run free-ports` ([scripts/free-ports.mjs](scripts/free-ports.mjs)) kills whatever is listening on 3001/5173/5174 (`-- 3000 3001` for specific ports). `predev` only *reports* busy ports and prints that command, and the server's `EADDRINUSE` handler does the same instead of dumping a stack trace — neither kills anything on its own. The `free-dev-ports` skill ([.claude/skills/free-dev-ports/](.claude/skills/free-dev-ports/)) is the PowerShell equivalent.

## Architecture

### Monorepo

- **`@igra/shared`** — pure TS compiled with `tsc -b`. Single source of truth for types, constants, socket event contracts, `GAME_DEFINITIONS`, content validators and built-in content banks. All three other packages consume its **compiled `dist/`**, so it must be rebuilt after any change there.
- **`@igra/server`** — Node + Express + Socket.io, ESM (`"type": "module"` — imports in compiled output need `.js` extensions). Rooms live in an in-memory `Map` and are lost on restart (acceptable).
- **`@igra/host`** — React + Vite + Zustand + Framer Motion + Howler. TV screen, `base: '/host/'`.
- **`@igra/controller`** — React + Vite + Zustand, PWA via `vite-plugin-pwa`, `base: '/play/'`.

### Socket contract

[packages/shared/src/types/events.ts](packages/shared/src/types/events.ts) defines `ClientToServerEvents` / `ServerToClientEvents` — the canonical client↔server contract. **Every new socket event goes through it.** Most gameplay does *not* need a new event: game actions ride the generic `game:player-action` (and host-owned flow control rides `host:game-action`).

### Adding a game — six wiring points

Miss any one and the game breaks end-to-end:

1. `GameDefinition` in [packages/shared/src/games/registry.ts](packages/shared/src/games/registry.ts) (`id`, `name`, min/max players, `supportsHostless`, …).
2. Server module in `packages/server/src/game/games/<id>/` implementing [IGameModule](packages/server/src/game/IGameModule.ts) (`onStart`, `onPlayerAction`, `onTick`, `onPlayerDisconnect`, `onEnd`, plus optional `validateStart`, `onHostAction`, `getAwardCandidates`). Extend `BaseGameModule` for no-op defaults.
3. Register the module in [packages/server/src/socket/setup.ts](packages/server/src/socket/setup.ts).
4. Host component + lazy entry in [packages/host/src/games/registry.ts](packages/host/src/games/registry.ts).
5. Controller component + lazy entry in [packages/controller/src/games/registry.ts](packages/controller/src/games/registry.ts).
6. A `GAME_RULES` entry in [packages/server/src/uputstva-page.ts](packages/server/src/uputstva-page.ts) — the public `/uputstva` hub lists only games that have one, so the game silently disappears from it otherwise.

Optional knobs a game opts into rather than reinvents: `GAME_ROUND_CONFIG` ([round-config.ts](packages/shared/src/games/round-config.ts)) for the round-count selector (UI options + server clamp in one place), and `GAME_TIMING_DEFS` for admin-tunable wait durations (see below).

### GameManager — privacy and lifecycle rules

[GameManager](packages/server/src/game/GameManager.ts) runs a 1s tick loop (per-module override below) and owns the two-channel state emission:

- `game:state-update` — room-wide broadcast with `playerData` **stripped**. Anything a controller may see goes in the shared/`hostData` half.
- `game:player-state` — per-player slice carrying only that player's private data.

**Secret information must never enter the broadcast half** — that's the recurring bug class across Gluvo doba, Špijun, Tajni agenti, Zavet and Kviz (unrevealed answers). Card faces, roles, correct indices and unrevealed words stay server-side until the reveal phase.

Two cross-game patterns worth knowing before touching any module:

- **Snapshot-based early-exit** — collection phases snapshot the expected player-id set at phase entry and check completion against it. Mid-grace disconnected players stay in the snapshot (so a sleeping phone doesn't shrink the denominator and steal a slot); past-grace removal via `onPlayerDisconnect` prunes it.
- **Per-game score reset** — `startGame` zeroes every `player.score` before `onStart`. Don't re-implement it inside a module.

**Fast tick + frame deltas** (used only by Splav so far): a module may declare `tickIntervalMs` and get its own simulation loop instead of the 1s one — the other games are untouched. A fast-tick module receives the **real elapsed time** as `deltaMs` (capped at 100ms so a stalled event loop can't teleport a simulation), while the 1s path keeps its exact `1000`. Such a module must **not** return a `GameState` from `onTick`/`onPlayerAction` on movement: it publishes positions through `getPendingFrame()`, which GameManager broadcasts as the tiny `game:frame` event (same delta trick as `getPendingOpsAppend`). Full state stays the authority for phases, rosters and scores. Note that even a once-a-second full state usually goes out as a lightweight `game:timer` — `stateSignature` zeroes `timeRemaining`, so a state whose only change is the clock never re-broadcasts.

At game end, `getAwardCandidates()` plus a generic score-based layer feed `allocateDiplomas` ([awards.ts](packages/shared/src/games/awards.ts)) so every player leaves with a consolation diploma.

### Rooms, reconnection, disconnects

- Room codes: `ROOM_CODE_LENGTH` (3) uppercase chars excluding `O/I/L`. Generation is **bounded** — at `MAX_ROOMS` (200) or after 100 collision retries the create call returns `null` and the handler answers "server full". Never loop unbounded there; an exhausted code space used to hang the event loop.
- Reconnect tokens (UUIDs) live in the controller's localStorage and travel via `socket.handshake.auth`. On disconnect the server starts a `RECONNECT_GRACE_MS` (5 min) timer; reconnecting inside it restores seat, score, and replays the current phase.
- Two distinct events: `room:player-left` is the **transient** grey-out on disconnect; `room:player-removed` is **permanent** (grace expired or kicked). Destructive `onPlayerDisconnect` work is deferred until grace expires so blips don't burn turns.
- A returning player who lost their token can **reclaim** a disconnected slot by joining with the same name (score and avatar preserved).
- **Server-initiated disconnect quirk**: on `sock.disconnect(true)` socket.io-client does *not* auto-reconnect, so the controller manually calls `socket.connect()` when the reason is `"io server disconnect"` ([controller App.tsx](packages/controller/src/App.tsx)).
- Rooms are **not** deleted when the last player leaves — the room belongs to the host.
- Abuse guards for public deploys: per-socket rate limits in [rate-limit.ts](packages/server/src/socket/rate-limit.ts), server-side name clamping, 512KB `maxHttpBufferSize`.

### Remote host & hostless rooms

Any one player can claim the host controls from their phone (`player:claim-remote-host`); the holder renders a phone mirror of the game-select screen and may start/stop games. Server-side permission checks accept either the host socket or the remote-host (`canControl` in [handlers/game.ts](packages/server/src/socket/handlers/game.ts)).

Rooms can also be created with no TV at all (`player:create-room` → `hostless: true`, creator auto-gets the claim). Only games with `supportsHostless: true` may start there (validated server-side). Hostless controller UIs key off `room.hostless` and render what the TV would have shown (full leaderboards, spectator canvas, the geo map, audio/video playback…). **TV-mode phone UX stays deliberately unchanged** — with a TV present, players should look at the TV.

### Drawing data flow

Controllers collect touch points in **normalized 0–1 coordinates**, batch every ~50ms, and emit; the host scales back up to its canvas size. Never send absolute pixels — devices differ in aspect ratio. Drawing ops are appended via the tiny `game:ops-append` event (`getPendingOpsAppend`) instead of re-broadcasting a growing state array (that was O(n²) traffic per turn).

## Content: packs, admin, timings

Most games' content is **file-backed JSON packs** in repo-root directories (`question-packs/`, `ko-sam-ja-packs/`, `tajni-agenti-packs/`, `gluvo-doba-packs/`, `spijun-packs/`, `asocijacije-packs/`, `fibbage-packs/`, `bitka-maps/`), each with an env override. Shared validators live in `packages/shared/src/games/*-import.ts` and are used by both the runtime and the admin API.

- **Manifests carry answers** (kviz *and* Lažov), so the public `GET /api/<x>-packs` endpoints return **summaries only** — only pack ids ride `host:start-game` and the server resolves the questions from disk; and the kviz asset mount serves only files one level inside a pack folder and never `*.json`.
- **Reads are lax, writes accept drafts**: a pack that fails the strict in-game check stays editable but invisible in-game (`visibleInGame` + `error` in the API response).
- **Admin SPA** at `/admin` ([admin-app.ts](packages/server/src/admin/admin-app.ts)), gated by `ADMIN_TOKEN` (`X-Admin-Token` header). One TS template literal containing the whole page — its inline CSS/JS **must avoid backticks and `${`** (the only `${…}` are real TS interpolations). Same constraint applies to the other inline-HTML pages: landing (in [index.ts](packages/server/src/index.ts)), [/uputstva](packages/server/src/uputstva-page.ts), [/gluvo-doba](packages/server/src/gluvo-doba-page.ts), [/kviz-generator](packages/server/src/kviz-generator-page.ts). Shared server helpers: [admin-common.ts](packages/server/src/admin/admin-common.ts) (requireAdmin, slugify, atomic writes), API router [content-admin.ts](packages/server/src/admin/content-admin.ts).
- **Question feedback** (report-as-wrong + 1–5 rating) is collected live from the player popup and persisted to `quiz-feedback.json` keyed by **source**, not by runtime id (`pack:<packId>:<index>`, `bank:<index>`), so the admin editor can join it back to a pack's questions by position. One bookkeeper serves every game that draws quiz packs — [QuizFeedbackTracker](packages/server/src/game/quiz-feedback-tracker.ts), used by **Kviz, KvizAtar and Vrući krompir** — because the same question asked in a different game must land under the same key, or a pack stays wrong while the reports sit in a game nobody checks. The action (`quiz:feedback`) is accepted in **any phase and for any question of the current match**, including one that already left the screen: the phone keeps a short history ([quizFeedbackStore.ts](packages/controller/src/store/quizFeedbackStore.ts)) and the popup offers "prijavi prethodno" next to the current one. That exists because a question only looks wrong once the correct answer shows, by which time the screen has moved on — gating reports to the current question is what kept the worst questions unreported. The history is filled by a **module-level subscription** to the game store, never by the menu component, which only exists while the popup is open. Each surface needs the runtime question id in its state (`data.questionId` for kviz, `question.id` on the bitka and hot-potato views) — it carries no part of the answer, and without it a question simply cannot be reported.
- **Timing editor** ("Timinzi" view) tunes **wait/pause durations only** (results, leaderboard, intro, narration) — never active-input timers, which stay hardcoded as gameplay balance. Tunable fields are declared in [GAME_TIMING_DEFS](packages/shared/src/games/game-timings.ts); modules resolve their slice at `onStart` and read `this.timings.KEY ?? KEY_CONST`, so the module constant is always the runtime fallback. Overrides persist to `timing-config.json` (gitignored).
- **Data admin** ("Podaci" view, [data-admin.ts](packages/server/src/admin/data-admin.ts)): zip backup of all content + factory reset from `SEED_DIR` (deploy mode only — reset is refused in dev so it can't wipe the tracked repo).

## Games

All 18 game ids are in [registry.ts](packages/shared/src/games/registry.ts); server modules, host and controller components all live under matching `<id>/` folders (KvizAtar is the one exception — its id is `osvajanje` and its folders are `bitka/`). Non-obvious things worth knowing:

- **Kviz** (`quiz`) — the unified quiz that absorbed several former standalone games. Every question has a `type`: `obicno` / `audio` / `video` (YouTube) / `geo` (pin on map) / `broj` (slider) / `emoji` (fuzzy free text). The phase machine (`showing-question → answering → showing-results → leaderboard`) is type-independent; types only change what renders and which action is accepted. Scoring caps at 1000/question for every type ([scoring.ts](packages/server/src/game/games/quiz/scoring.ts)). Types + validator: [quiz.ts](packages/shared/src/types/quiz.ts), [quiz-import.ts](packages/shared/src/games/quiz-import.ts). Geo pins travel as normalized `{x,y}` and are reprojected via [serbia-projection.ts](packages/shared/src/games/serbia-projection.ts) (use `packLatLngToPin`/`packPinToLatLng` anywhere a pin meets a question — they pick mercator-bbox vs the calibrated Serbia projection). Pack selection is multi-select plus an optional question-type filter.
- **Zavet** (id stays `bolji-zivot`) — Cabo-style memory card game, **lower score wins** (`lowerScoreWins` in the registry; leaderboards sort ascending — don't reuse descending components). Private peeks are sub-phase-scoped and never replayed on reconnect (memory *is* the game). Full rules: [docs/bolji-zivot-dizajn.md](docs/bolji-zivot-dizajn.md).
- **Gluvo doba** — Mafia/Werewolf with Slavic-mythology roles. Roles are **data** ([gluvo-doba-roles.ts](packages/shared/src/games/gluvo-doba-roles.ts)) and night resolution is a **pure function with a strict order** ([night-resolution.ts](packages/server/src/game/games/gluvo-doba/night-resolution.ts)) — add roles by extending the tables and the pipeline, not with if-branches. Anti-tell rule: every living player gets a visually identical night grid.
- **Tajni agenti** — three modes (`classic` / `duet` / `coop`) with different team, key and turn-budget rules, picked at game-select and re-validated in `validateStart`.
- **Asocijacije** — always a single board (deliberately *not* in `GAME_ROUND_CONFIG`); klasik and kviz modes.
- **Penali** — the only `supportsHostless: false` game and the only 3D one. three.js lives exclusively in the host's lazy `penali` chunk ([PitchScene.ts](packages/host/src/games/penali/PitchScene.ts), vanilla three, no react-three-fiber, no assets — everything is primitives), so the main bundle is unaffected. Shooter and keeper commit **blind and simultaneously**: during `aiming` only commitment booleans may enter `hostData`, never the aim or the chosen zone. Balance constants in [penali-rules.ts](packages/shared/src/games/penali-rules.ts) were tuned by simulation (~73% goals / 24% saves; a shot down the middle is worth ~68 expected points against ~120 for one placed near a post) — re-simulate before changing them. A keeper who lets the clock run out scores 0 even if the ball comes to them, and the auto-shot for a timed-out shooter is jittered, so neither side can farm points by doing nothing.
- **Složilica** — word builder backed by a 252k-word Serbian dictionary at `packages/server/assets/recnik/sr-recnik.txt` (static asset, **not** `DATA_DIR` content; ships in the Docker image via the existing `assets/` copy). Loaded **lazily and cached** by [recnik.ts](packages/server/src/recnik.ts) — only the first word game in the process pays the ~16 MB. `validateStart` refuses the game if the file is missing rather than running a game where nothing validates. Regenerate with `npx tsx scripts/build-recnik.ts`; sources and licences are in LICENSE.md. Anti-leak: during `pisanje` only per-player word *counts* go in the broadcast — never the words, and never `bestPossible`.
- **KvizAtar** (id is still `osvajanje`, folders are `bitka/` — the game was renamed after launch and renaming an id would mean migrating saved timings and host settings) — Triviador/Konquiztador: 2–4 players, one castle each, questions decide who expands and who takes whose land. **How many players fit is a property of the map, not a constant**: the strict map check stays at `BITKA_MIN_TERITORIJA` (9) so a small map remains valid for two, and `validateStart` refuses the *start* when the chosen map has fewer than `bitkaMinTeritorija(players)` (3 per player — one castle + two to conquer) or fewer marked castle sites than players. Without that, the last player in the placement queue can end up with no site at all. The no-map-chosen fallback (`firstValidBitkaMapIdSync`) takes a minimum-territory hint so a four-player table doesn't default to the alphabetically-first tiny map. **Length is a game-select choice** (`bitkaMode`, deliberately *not* `GAME_ROUND_CONFIG` — that selector is a bare round count and can't express "until the last castle"): `zamkovi` runs the war until one castle stands (~25 min; `BITKA_MAX_RATNIH_RUNDI` stays a stuck-game guard, not a setting), `runde` plays `BITKA_RUNDE_IZBOR` (6/9/12) rounds and then ranks by score. **Turns always rotate — with one exception**: while a besieger keeps breaking walls they hold the turn and get a fresh question against the *same* castle (`duel-rezultat` in the module). That chain is self-limiting (three walls) and never idles anyone, since both duellists are on their phones; a general "attack again on any win" rule was considered and rejected because it lets one player run the board while the others watch. In a two-player game that chain can end the match before the opponent moves — kept, but stated plainly in `/uputstva`. **A war round ends when the turn pointer wraps back to where the round started** (`roundStartPointer`), never on an attack count: counting attacks against `alive.length` taken *after* an elimination let a round close with the last player never having attacked. Each round starts one seat further along (`beginRound`), so the same player doesn't open every round. **A disconnected player never holds the table**: their `napad-izbor` is skipped on the spot ("nije tu — potez ide dalje") and their castle/land picks auto-resolve immediately instead of running the 14/8 s timers. `IZBOR_DURATION` is 8 s (was 12 — an adjacent pick is usually two or three options). **`kraj` is the final beat** (`KRAJ_DURATION`, tunable, 6 s): same board *not* remounted (so the `pobeda` confetti actually plays on it), an Objava with the winner and the sentence that ended the war (`lastEvent`), leaderboard with eliminated/removed players ranked **below** every survivor regardless of score — note the platform's own final screen still ranks by `player.score`, documented in `finishGame`. Scoring is made visible instead of assumed: `scoringLegend` rides `hostData` during `uvod` only, land messages carry the points ("uzima Porodin (+200)"), and `duel.scoreDeltas` goes out with `pendingOutcome` so `duel-ishod` can say "Pera +200 · Mika −200" (the commit pass warns if the real change differs). `poolWarning` (also `uvod` only) says when the chosen packs hold fewer questions than the match will draw, because the pool otherwise recycles silently. On the TV the `duelArena` layout became a general **question arena** for every answering and reveal phase (the 4.4 rem strip under a 76 vh map was unreadable from a couch), the pick-phase Objava sits at the bottom edge with a light dim so the offered territories stay visible, and the 3D board shows the owner's emoji over each castle. On the phone a tap on a non-offered territory is answered (red outline, haptic, "Nije susedna tvojoj zemlji") with a 22 px fat-finger fallback to the nearest offered one, every answer screen shares one `Clock` header and one `SubmittedBar`, and an eliminated player keeps the normal spectator screen with a "🏳️ Ispao si" chip instead of a bare map. **Maps are content, not code**: drawn in `/admin` → Mape over an uploaded PNG and stored in `bitka-maps/<id>.json` (+ `<id>/` holding the image, served at `/bitka-files/<id>/<file>`). Maps are *illustrations*, so there is **no geography** — no lat/lng, no bbox, no `serbia-projection`; every coordinate is normalized `{x,y} ∈ [0,1]` over the image, the same space the kviz geo pins use. Questions come from the ordinary kviz packs via the shared `quizPackIds` field (obicno/uljez/**matrica** for the land grab and duels, broj for the tiebreaker; `pogodi-broj` is the fallback and, failing that, speed decides). **Eight types are playable** — `BITKA_PITANJE_TYPES` = obicno/uljez/matrica/redosled/domino/emoji/dopuna/anagram, plus `broj` for the tiebreak (`BITKA_QUIZ_TYPES`). Only three kviz types are refused: audio/video (media — the TV already carries the board and a hostless room has nowhere to play it), geo (a second map, when the map *is* the battlefield) and piksel (needs the progressive de-pixelation pipeline). **Every type plays in both places** — the land grab and the duel draw from one pool, so "add a type" never means "add a phase". The text types (emoji/dopuna/anagram) carry a known, accepted cost: typing puts thumb speed into the outcome, and a miss may be retried until the clock runs out (a typo must not cost a castle, and the checker already tolerates small ones), so a duel on them usually runs the full 20 s instead of ending the moment both answer. They are worth checking on deliberately rather than leaving every type on. Anagram is **not** progressively unscrambled the way kviz does it — a 20 s duel does not need a fourth timing state or another surface for the answer to leak through, so `scrambleOf` shuffles once at `setQuestion`. Domino is the one type that isn't a single move: the player walks the chain and stops at the first miss, so `answers` is written only when they're done and `materializePartial` credits the partial streak at phase end (otherwise four correct steps would be worth as much as none). Its per-step reference + next term ride `playerData` alone, while the broadcast carries `dominoProgress` — step counts only, no values, which is what lets the TV show the race. **Every answer reduces to `{score, remaining}`** ([BitkaState.ts](packages/server/src/game/games/bitka/BitkaState.ts)) and all three decisions read only those: the land-grab pick queue sorts by score then speed, `resolveScoredDuel` gives the land to the higher score and returns `'tiebreak'` only on a true tie, and `qualifyThreshold` (half the max, rounded up) is the bar for the two spots where there is nobody to compare against — who may pick in the race, and an attack on a neutral territory. For choice and text questions every score is 0 or 1, so all of that is literally the old rule; the graded types slot in with no extra branch — matrica scores 0–3 (cells hit), redosled 0–n (items in the right place), domino 0–n (streak before the first miss) — and because 2:3 is already a decision they **reach the tiebreak less often, so a graded type makes the game shorter**. **The game-select type filter is what makes a new type reachable**: the config popup renders the ordinary kviz pack picker for `osvajanje`, so `host:start-game` has always carried `quizTypes` — but `BitkaModule` ignored it, making the checkboxes a control that did nothing. It honours the filter now (`parseTypeFilter`, intersected with `BITKA_QUIZ_TYPES` and falling back to the unfiltered pool if it empties), the filter applies to the question pool only (the number pool is machinery — "only matrica" must not mean "no tiebreak"), and both pickers (TV and the hostless phone) now offer only the four types the game can place instead of chips for geo/audio/video it discards. This matters more than it sounds: **matrica is ~3% of the packs (31 of 1017 usable questions), so across a ~20-question game the expected count is 0.6** — leave every type checked and a new type simply will not show up. Checking it is how you ask for it. **New types have no fallback, deliberately**: they live in dedicated packs (`matrica.json` is all matrica), so pulling a reserve the way `pogodi-broj` backs the number question would turn "I picked history" into a game of grids nobody asked for — pick a pack without them and the game stays a choice game. A pack with no usable question at all still falls back to the built-in bank. **What is public is the prompt, never the answer**: matrica's nine cells, redosled's *shuffled* items, domino's button labels and step count, the emoji/quote/scramble. The reveal fields (`correctIndex`/`correctCells`/`correctOrder`/`correctText`/`dominoChain`/`explanation`) are reveal-only and the private picks (`selectedCells`/`selectedOrder`/`myText`/`lastWrongText`/`domino`) ride `playerData` — all enforced by the test's leak scanner, where `domino` is checked as a **key** (`"domino":`) because as a bare word it collides with `"kind":"domino"`. Each type renders from one component per package (`BitkaMatricaGrid`/`BitkaNewTypes` (with `BitkaScoreRow` as the one score row) on the TV, `BitkaMatricaCells`/`BitkaNewTypes` on the phone) reused by the answer screen, the reveal, `DuelSpectator` and the hostless strip, and every reveal carries a `score`/max row — with a graded type, "tačno/netačno" hides the very thing that decided the duel. Everything except domino is submitted **once**, on a confirm button: the rule is one answer per question, and separate taps would raise the question of who locked in first. Shuffling (`shuffledItems`, `scramble`) happens in `setQuestion`, not in `buildGameState` — state goes out on every tick, so deriving it there would reshuffle the list under the player's thumb. A question's `imageUrl` *is* honoured on every surface: TV panel (a thumbnail beside the text, plus a smaller one on the tiebreak strip), the answerer's phone screen and the hostless strip, all through `BitkaQuestionImage` / `QuestionImage`, which drop themselves if the image fails to load. **The pack name rides along as the question's category** (`packName` on `BitkaQuestionView`, from a `packNames` map the module keeps because `loadPools` flattens every pack into one pool): gold uppercase above the question text on the answer screens, `DuelSpectator` and the hostless strip. **Phone only**, like the same strip in Kviz — the TV panel already carries the map, the target and the points. The built-in bank has no name and the number question is left without one on purpose: the intro measure and the tiebreak are machinery whose pack the server picks (`pogodi-broj`), so a category there would name something the host never chose. Attack resolution is a **pure function** ([duel.ts](packages/server/src/game/games/bitka/duel.ts)) — change outcomes there, not with if-branches in the module. **Castles are placed in turn**, ordered by the intro number question (`baseQueue`): only the active player gets `selectableIds`, each placement is committed immediately and visible to everyone, so later players choose tactically against the castles already on the map — there are no collisions and therefore no re-pick rounds. Both land-grab picks and attack targets are restricted to territories adjacent to what you already hold, falling back to the whole map when nothing adjacent qualifies (`freePickTargets` / `attackTargets`) — so a boxed-in player never loses their turn. **Hostless rooms get a "TV strip"** ([BitkaHostlessPanel.tsx](packages/controller/src/games/bitka/components/BitkaHostlessPanel.tsx), rendered only when `room.hostless`): the question and its options for players who aren't answering (a duel spectator otherwise sees nothing), per-player chips for who answered / who is picking, the pick queue, the round context line, the full duel-outcome sentence, and an always-on mini scoreboard. With a TV present none of it renders — that screen already carries it. The event derivation that drives the TV's 3D effects lives in `@igra/shared` ([bitka-fx.ts](packages/shared/src/games/bitka-fx.ts)) precisely so the phone can reuse it for a territory flash, CSS flames over a burning territory (`.bitka-fire` — the phone-side counterpart of the TV's three.js fire, since the controller never loads three) and haptics, with both surfaces speaking one event vocabulary and one timing plan (`planFxTiming`). Server state carries the *new* owner immediately while effects are deliberately delayed, so both surfaces render a **deferred board** (`planFxHolds` + a `shownBoard` state, never `host.board` directly) — the map lags exactly long enough for the impact to land before the colour turns; deriving that in an effect alone would flash the new colour for one frame, since passive effects run after paint. **The reveal happens on the question screen, not the map screen**: `*-rezultat` keeps the question and its options up and stamps each player's avatar onto the option they picked, with the correct one green and checked (TV panel, the answerer's phone screen, and the hostless strip all render it the same way from `hostData.results`, which already carries per-player `optionIndex`). **A duel reveals in two steps before anything touches the board**: `duel-odgovor-rezultat` holds the choice question up with the correct option and both avatars, and a drawn duel then gets `duel-broj-rezultat` for the number — correct value, both guesses closest-first, and each duellist's confirm time, since speed is what splits equal guesses. Then comes **`duel-ishod`, a window that reports the outcome while the board is still untouched** — "Porodin menja gospodara", "jedan zid manje" — on both surfaces, for `DUEL_ISHOD_DURATION` (4 s). That one exists because the FX derive from a board diff: `applyDuel(room, win, commit)` runs **twice**, first with `commit: false` (compute the outcome, write `lastEvent` / `lastOutcome`, touch nothing else) and then, when the window closes, with `commit: true` (owners, walls, bonuses, scores) — which is the moment `deriveFxEvents` sees a changed board and the weapon flies. The preview pass must **not** publish `duel.outcome` (FX key off its appearance); it sends `pendingOutcome` + `wallsAfter` instead, and the `zid` sentence computes the remaining wall count rather than reading it off the board, which is still one higher. Both reveal steps share one tunable knob, `DUEL_OTKRIVANJE_DURATION` (3 s); the window has its own. Note what this costs: a duel is ~7 s longer, ~10 s through a tiebreak — turn those knobs down in /admin → Timinzi if the war drags. **Every question reveals, including the ones that only decide a tiebreak**: the intro number question reveals on its own screen (`redosled-rezultat` keeps the broj question up with the correct value and everyone's guess, closest first), and a drawn duel reveals its number on `duel-broj-rezultat`. **Each question reveals exactly once, on its own screen** — `duel-rezultat` is deliberately *not* a reveal phase (`showQuestion` / `revealing` in `buildGameState` both exclude it), so the server sends no question, no `correctIndex` and no `results` there and the TV panel, the phone and the hostless strip all fall back to the outcome sentence alone. Re-showing it over the map meant reading the same answer a third time on top of the one screen that has something else to show. That also retired the whole two-questions-on-one-screen apparatus: `hostData.tiebreak`, `BitkaTiebreakView`, the host's `TiebreakStrip`, the controller's `BitkaTiebreak`, the `choiceResults` snapshot and `DUEL_TIEBREAK_EXTRA` are gone, because `state.answers` may now be overwritten by the tiebreak — the choice round was already shown. **A duel is announced inside the countdown, not before it**: entering `duel-pitanje` puts up one Objava that names who attacks whom, for which territory, its walls and its points, while its circle counts down to the question — announcement and counter are ONE element, so the phase lasts just `PITANJE_NAJAVA_DURATION` (the earlier separate announcement card and its `BITKA_NAJAVA_MS` extra beat are gone; a duel is ~2.5 s shorter, and both TV and phone show the card the whole phase off the same server clock). A siege turns the whole Objava red (`--danger`, pulsing) and carries the wall state — the only attack that can eliminate a player. **A continued siege gets no full announcement** (`opsadaNastavak` on the duel view, from `beginDuel(..., continuation)`): same attacker, same castle, so it would repeat up to three times inside one attack — its Objava keeps only the counting circle and the "opsada se nastavlja" line. The TV dims the board under it rather than blurring it — `backdrop-filter` over the WebGL canvas can snapshot black, which turns the board into a hole. **`*-pitanje` is a countdown, not a preview**: the server does not put the question in the broadcast at all during `redosled-pitanje` / `osvajanje-pitanje` / `duel-pitanje` (`showQuestion` in `buildGameState`), and both surfaces draw the translucent central **"Objava"** over the board instead — the one info element every in-game message uses (left circle with the countdown number or an outcome glyph, gold uppercase overline, one-sentence title, sub-line; plain `rgba` dim, never `backdrop-filter` over the WebGL canvas). During `osvajanje-pitanje` its title carries the consequence of the previous move (`lastEvent` — "Pera uzima Porodin"): the countdown and "what just happened" share the beat, so they share the element. The same Objava carries the pick phases (`baza-izbor` / `osvajanje-izbor` / `napad-izbor`: who picks, the queue and the remaining time — the header clock and the bottom strip hide while it stands, so one sentence appears in exactly one place per frame) and the no-winner reveal (`osvajanje-rezultat` with no correct answer: grey border, 🚩 circle, the correct answer in the sub-line instead of the option grid); `duel-ishod` renders as its glyph variant with the dim raised to 0.58. Before this the question text appeared beside the map the moment the phase started and then again full-screen seconds later, so the same question was read twice in two places; now the pause only says *when* to look up, and everyone opens the question in the same instant. Nothing but the counter may go there — put the question back and the leak is back. **The phone's status line is a centred mini-Objava** (`StatusCard`): who is picking, who just took what — and in the pick phases it also carries the overline and the countdown circle, so the sentence and the clock live in one place (the hostless strip drops its duplicate title there and keeps only the queue and the rule). It used to be small text at the top edge over a colourful map, which is where it went unread. It is suppressed in `duel-rezultat` — that screen belongs to the capture animation and nothing may sit on top of it. **`duel-odgovor` / `duel-broj` get their own TV layout** (`duelArena` in BitkaHost): map, target card and a one-line standings table squeeze into a left column, and the question takes the rest of the screen with a slot per duellist reading `zaključao ✓` / `razmišlja…`. Those two slots come straight from `attackerCommitted` / `defenderCommitted` — the two booleans the server sends precisely because *what* was picked may not enter the broadcast. The header clock doubles in size there and the whole header keeps right padding, since the host's `Završi igru` button owns that corner. **Everyone who isn't in the duel gets the same question on their phone, read-only** (`DuelSpectator`): plain tiles instead of buttons, the two lock-in chips, and the countdown — and it stays through the two reveal steps, which is a spectator's only chance to see what the answer was. The question is already in the broadcast half, so nothing new is revealed; this is the one place where the TV-mode phone deliberately does show the question, because a duel otherwise leaves half the table looking at a map with no idea what is being asked. It ends with the duel — the outcome is still watched on the map. **The outcome lands with a weapon**: `deriveFxEvents` emits `mac` (attack went through) or `stit` (defence held) next to the existing events, and everything that follows from the hit — the wall going out, the colour turning — waits `FX_SLAM_SECONDS` for it to land, on top of the projectile's flight. All three surfaces draw the same beat from the same event: the 3D board and the flat FX canvas build it from primitives (blade, guard, grip, pommel / disc, rim, boss), the phone slams the ⚔️/🛡️ glyph over the territory in CSS (`.bitka-slam`). **On the phone `duel-rezultat` is the one reveal that stays on the map** (`duelReveal` in the controller — `osvajanje-rezultat` still gets the full-screen option grid): the payoff of a duel *is* the map — wall burning, land changing hands, castle falling — and it fires the instant the phase flips, so a full-screen question hides exactly what the player just won (the FX only replays later when the map returns, or never, if that hit ended the game). Duellists get the map plus a compact `Reveal` line / hostless strip; the full reveal is the TV's job, per the usual rule that a phone doesn't duplicate a TV in the room. Related: [BitkaMapPicker.tsx](packages/controller/src/games/bitka/components/BitkaMapPicker.tsx) seeds its played-FX cursor from whatever events exist **at mount**, because the map is unmounted and remounted all game (question, slider) and would otherwise re-flash the previous turn's hit on every return. Without all this the map simply changed colour with no visible reason. Only then does `osvajanje-izbor` come up, and it is deliberately bare — no question, no answer — because that screen is about the map. An earlier version merged the two (pick immediately, answer shown alongside) and was reverted: the reveal is worth its own beat, and mixing it into the pick screen buried who answered what. On the phone the map takes the **whole screen** (a fixed, full-bleed stage that breaks out of `#root`'s padding; titles and hints float over it), so the target list and the score table both live in the player popup instead ([BitkaBoardMenu.tsx](packages/controller/src/components/BitkaBoardMenu.tsx), rendered by `PlayerMenu`). Unlike the other games it renders in TV rooms too — a player who isn't on turn otherwise has no idea where anything is happening. **TV-only 3D board + FX**: on the TV the map is a three.js scene ([fx/](packages/host/src/games/bitka/fx/)) — each territory is its own extruded slab, raised when focused, with castles/walls as primitives (the castle of whoever is on turn scales up and pulses); the camera pushes in on the duelled territory and pulls back out. Territory names are **not** drawn on the TV (the panel names them in prose), and the 3D canvas is deliberately not aspect-locked to the map image — the camera frames the board into whatever box the layout gives it, by bisecting for the closest distance at which all eight board corners still project inside the frustum. That corner check matters: the camera is tilted, so the near edge enters the frame far more narrowly than a flat "fit the depth into the height" estimate suggests — that estimate silently clipped the near corners while leaving a large empty band above the far edge. **Any uploaded map works with zero extra content**, because `ExtrudeGeometry` derives UVs straight from the shape coordinates, so a polygon drawn in the stored `[0,1]` space picks up exactly its own slice of the PNG; a darkened full-image plane sits under the slabs so the parts of the illustration that aren't territories stay visible. `?board=2d` on the host URL falls back to the flat map with a transparent FX canvas over it, which is also the automatic fallback when WebGL is missing and the `Suspense` placeholder while the three chunk loads. Both surfaces animate attacks, defences, captures, wall hits, castle falls and the win. Events are derived by a **pure diff of two consecutive `BitkaHostData` snapshots** ([bitka-fx.ts](packages/shared/src/games/bitka-fx.ts)) — no new socket events, no server involvement, each event fires exactly once, and a repeated state (reconnect/replay) produces nothing. The scene ([BitkaFxScene.ts](packages/host/src/games/bitka/fx/BitkaFxScene.ts)) follows the Penali rules: vanilla three, no assets, primitives only, and it lives behind a `lazy()` boundary so three lands in its own chunk (`BitkaFx-*.js`) — the main bundle and even the `BitkaHost` chunk stay free of it. Its ortho camera is the normalized `[0,1]` map space, so FX coordinates are the same ones the polygons use. **Effects are decorative and must stay short** (the weapon is the longest at `FX_SLAM_SECONDS` 1.45 s of fall + 0.5 s hold ≈ 2 s, against the 3 s minimum of `DUEL_REZULTAT_DURATION`; a castle-fall cascade can exceed that and simply gets cut). `FX_SLAM_SECONDS` is the shared clock for both surfaces, so the phone's `.bitka-slam` / `-flash` / `-ring` keyframes carry hand-computed percentages that put the impact at the same absolute moment (72 % of 2 s) plus a matching `SLAM_MS` — change the constant and those three percentages move with it, or TV and phone land the blow in different beats: the server clock never waits for the TV, and `clear()` drops everything mid-flight. Phones never load any of this — the controller package has no three dependency, which is what keeps hostless simple; that layer is the intended seam for a later extruded-3D board. The map's strict check (≥9 territories, connected neighbour graph, image present) is what gates `visibleInGame`; a half-drawn map stays editable but never reaches game-select. Headless end-to-end + anti-leak run: `npx tsx scripts/test-bitka.mts` (`--players 2..4`, `--rounds n`, `--map id`, `--pack a,b` / `--pack all`, `--types a,b`). **Without `--pack` the game reads nothing off disk** — it falls back to the built-in bank, which has no matrica, so a bare `--types matrica` proves nothing; `--pack all` is what the TV sends when the host doesn't touch the pack selection. `--pack matrica` also exercises the `pogodi-broj` tiebreak fallback, that pack carrying no number question.
- **Lažov** (id is `fibbage`) — write a convincing fake answer to a trivia question, then pick the real one out of the pile. Content is **file-backed** like the other trivia games: packs live in `fibbage-packs/<id>.json` (`{ name?, description?, questions:[{text, answer, category?, accept?}] }`), are edited in `/admin` → Lažov, and are validated by [fibbage-import.ts](packages/shared/src/games/fibbage-import.ts). A manifest **carries the answers**, so it follows the kviz split rather than the Ko sam ja one: `GET /api/fibbage-packs` serves summaries only and the chosen ids ride `host:start-game` as `fibbagePackIds` to be resolved server-side ([fibbage-pack-resolver.ts](packages/server/src/game/games/fibbage/fibbage-pack-resolver.ts)). `FIBBAGE_QUESTION_BANK` stays in code purely as the **fallback** for an empty/bad pack folder — packs load asynchronously, so `showing-question` holds while `questionsReady` is false instead of running the writing timer against a question nobody has seen. Three scoring rules carry the whole game and none of them are visible from the screen, which is why [scripts/test-fibbage.mts](scripts/test-fibbage.mts) exists: **the truth bonus is paid once** — a player who types the real answer is an *auto-finder*, banks `TRUTH_POINTS` and is excluded from `expectedVoterIds` entirely (letting them vote as well paid it twice); **writing is the price of scoring** — someone who sits out the writing phase still votes but earns nothing for finding the truth, or doing nothing becomes the strongest play; and **identical lies merge into one option** that pays every author. The reveal attributes **every** lie, including the ones nobody picked (`revealOptions`, sorted by the module: 0-vote lies first, then rising vote count, truth last), and then spells out **who fooled whom** in words on all three surfaces ([FoolsBoard.tsx](packages/host/src/games/fibbage/components/FoolsBoard.tsx) on the TV, named lines on the hostless strip, and `fooledNames` / `fooledByNames` on the phone's own result card). The avatars beside each option are not enough on their own — across a room you register *that* somebody fell for a lie without ever registering *who*, which is the one thing players repeat out loud afterwards. `voterNames` rides on the reveal option itself precisely so all three render it from one field: the phone has no player roster and the hostless strip would otherwise join against the leaderboard. A round where nothing landed says so rather than rendering an empty section, and `SHOWING_RESULTS_DURATION` went 8 s → 10 s to fit the extra block. Headless end-to-end + anti-leak run: `npx tsx scripts/test-fibbage.mts` (`--players 4..8`, `--rounds n`, `--pack id`; a nonexistent `--pack` exercises the built-in-bank fallback).
- **Splav** — sumo on a shrinking raft, and the **first continuous-input game**: 2–8 players steer with a thumb stick and have one dash on a ~2s cooldown. Everything about it follows from two decisions. First, the **dash is the only way to eject anyone** — plain bumps use a low restitution and can't push someone off, while a dash multiplies what the victim takes (`SPLAV_DASH_PUSH`), locks the attacker's heading for its duration and is spent the moment it connects; that's what makes *when* to spend it the whole game. Second, **camping is designed out**: the raft shrinks (`splavArenaRadius`) *and* drifts (`splavArenaCenter`, a pure function of round time, so the safe spot keeps moving), and a shove is worth `SPLAV_ELIM_POINTS` (120) against 40 per place survived — hiding pays, pushing pays better. Credit is last-touch inside `SPLAV_CREDIT_WINDOW_MS`, so the shrinking edge finishing someone off still pays whoever hit them. Physics is a **pure step function** ([physics.ts](packages/server/src/game/games/splav/physics.ts)) in **arena units** (the raft starts as a unit disc at the origin) — naive O(n²) collisions, since 8 circles is a few dozen distance checks. Wire shape: the module returns `null` from `onPlayerAction` and from most `onTick`s and instead emits `SplavFrame` snapshots (~15/s, `SPLAV_FRAME_INTERVAL_MS`, counted in **accumulated ms not ticks** because a 25ms `setInterval` drifts); a full `GameState` goes out only on a phase change or an elimination. The TV renders `SPLAV_RENDER_DELAY_MS` behind live and **interpolates** between frames — showing the newest one directly stutters at 15fps. Eliminations travel as a **round-long array** with monotonic `seq`, not a "latest" field: two players can fall on the same tick, and the shove that ends a round arrives together with the round result (which is why the array is also kept through `runda-gotova`). The arena is plain **canvas 2D** ([SplavArena.ts](packages/host/src/games/splav/SplavArena.ts)) — everything is on one plane, so an angled top-down projection (squash Y, extrude the raft into a slab) reads as 3D without three.js in the bundle; the host component subscribes to `game:frame` **directly, never through the zustand store**, or React would re-render 15×/s. Not hostless: the arena *is* the game. Headless end-to-end + traffic run: `npx tsx scripts/test-splav.mts` (bots steer off the same frames a phone does).
- **Tutorial mode** (Gluvo doba, Zavet, Špijun) — phase timers stop ticking and the host advances phases via a `*:next-phase` host action. Only the boolean `tutorialMode` is shared; hints are computed client-side from each player's own `playerData` so nothing leaks.

## i18n

A deliberately **partial** EN/SR layer — don't assume everything is translatable. Strings and `translate()` live in [strings.ts](packages/shared/src/i18n/strings.ts) (flat dotted keys, `en → sr → raw key` fallback); host and controller each have a `useLanguageStore` (persisted per device, key `igra-language`, default `sr`) and a `useT()` hook. **Not room-synced** — TV and phone can differ.

Translated: platform chrome, game-select cards, and three games (Crtaj i pogodi, Slepi telefoni, Pronađi par). **Serbian by design**: every other game's in-game screens, validator error strings, and the built-in content banks. When adding a string to a translated surface add both `sr` and `en`; when touching an untranslated game, leave its strings Serbian.

The only server-side language plumbing is the draw-guess word bank (`language` rides `host:start-game` as a content hint).

## Serving & deployment

The Express server is the single public entry point.

- `/` static landing (no bundle, no room creation — safe for bots and link previews), `/host/` host bundle, `/play/` controller bundle. `/host` and `/play` 301 to the slashed forms (needs `strict routing` so the redirect doesn't loop).
- **Dev fallback**: when `packages/<pkg>/dist/index.html` is missing, Express proxies `/host/**` and `/play/**` to Vite. The check tests `index.html`, **not** the `dist/` folder — Vite leaves empty `dist/` dirs behind, which would flip the server into prod-static mode that serves only 404s. The inverse trap — a leftover `dist/` from an earlier `npm run build` making `:3001` serve a *frozen* bundle while Vite runs unused, so source edits appear to do nothing — is disarmed by the `predev` hook ([scripts/dev-clean.mjs](scripts/dev-clean.mjs)), which deletes both `dist/`s before `npm run dev` / `npm run dev:server`. On top of that, the static branch logs the served bundle's build timestamp and (outside `DATA_DIR`/production) a "rebuild or delete dist" hint, so a stale bundle is visible in the startup log.
- The proxy uses `pathFilter` (function form) rather than `app.use('/host', …)`: mount-stripping would turn `/host/` into `/` at Vite, which redirects back to `/host/` → infinite loop. `ws: true` carries both socket.io upgrades and Vite HMR.
- **LAN testing**: set `HOST_ORIGIN`/`CONTROLLER_ORIGIN` to your LAN IP so CORS accepts them; see [README.md](README.md).
- **Deploy** (Docker/Coolify): all editable content is file-backed and path resolution is centralized in [data-paths.ts](packages/server/src/data-paths.ts). With `DATA_DIR` set (baked to `/data` in the [Dockerfile](Dockerfile)) content lives on a persistent volume; `seedDataDirs()` copies bundled defaults from `SEED_DIR` **only into missing/empty dirs**, so redeploys never clobber admin edits. Without `DATA_DIR`, everything resolves to the repo-root folders (dev mode).

### Environment variables

`PORT`, `HOST_ORIGIN` / `CONTROLLER_ORIGIN` (CORS), `SAME_ORIGIN_DEPLOY`, `SINGLE_ROOM_MODE` (+ `VITE_SINGLE_ROOM` for the controller) — auto-fill the active room code; `ADMIN_TOKEN` (unset = admin disabled), `DATA_DIR` / `SEED_DIR`, the per-content overrides `QUESTION_PACKS_DIR` / `KO_SAM_JA_PACKS_DIR` / `TAJNI_AGENTI_PACKS_DIR` / `GLUVO_DOBA_PACKS_DIR` / `SPIJUN_PACKS_DIR` / `ASOCIJACIJE_PACKS_DIR` / `FIBBAGE_PACKS_DIR` / `BITKA_MAPS_DIR`, `TIMING_CONFIG_FILE`, `RECNIK_FILE` (Složilica word list; defaults to the bundled asset), `QUIZ_FEEDBACK_FILE`, `LOG_DIR` / `LOG_RETENTION_DAYS`, `HOST_DIST_DIR` / `CONTROLLER_DIST_DIR`.

## Gotchas

- After editing anything in `@igra/shared`, run `npm run build:shared` (or restart `npm run dev`) — consumers import `dist/`, not `src/`.
- Both Vite configs set `strictPort: true` because the dev proxy targets fixed ports. On "Port 5173 already in use", kill the stale process (the `free-dev-ports` skill does this) — without strictPort Vite silently shifts ports and `/play/` ends up proxying to the *host* dev server.
- If `/host/` or `/play/` 404s in dev — or serves code you know you changed — delete stale/empty `packages/{host,controller}/dist/` folders (see the dev-fallback rule above); `npm run dev` now does it for you.
- Inline-HTML pages are TS template literals: no backticks, no `${` in their embedded CSS/JS.
- The host's `history.replaceState` for `?code=` uses a **relative** URL so it keeps the `/host` path; an absolute one would land on `/` and trip the landing page.
- Windows machine, but bash idioms and forward slashes are expected.
