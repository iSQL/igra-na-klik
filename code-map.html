Every game touches all four packages — shared types, server module, host screen, controller controls. Empty cells mean the game doesn't need that layer.

@igra/shared — the contract

types/events.ts defines every ClientToServerEvents / ServerToClientEvents entry. New socket event? Add it here first.

games/registry.ts is the canonical GAME_DEFINITIONS list — host, controller, and server all read it.

Compiled to dist/ via tsc -b. Must rebuild (npm run build:shared) before others see changes.

@igra/server — the brain

GameManager runs a 1-second tick loop, routes game:player-action through each module's onPlayerAction.

Each game implements IGameModule with lifecycle hooks. setup.ts registers them all.

In-memory Map<string, Room> — rooms lost on restart. 5-minute reconnect grace window.

@igra/host + @igra/controller

Host = TV screen (Vite + React + Zustand + Framer Motion + Howler). Controller = phone PWA.

Both have a GameRouter that dynamic-imports the right component from games/registry.ts based on the room's gameId.

Server emits game:state-update (full state → host) vs game:player-state (private → individual controllers).

Five-place game registration

A new game lights up only after wiring in all five spots — any miss breaks the end-to-end flow:

  1. packages/shared/src/games/registry.ts — GameDefinition entry (shared)
  2. packages/server/src/game/games/<id>/ — IGameModule implementation (server)
  3. packages/server/src/socket/setup.ts — register the module instance (server)
  4. packages/host/src/games/<id>/ + host/src/games/registry.ts lazy entry (host)
  5. packages/controller/src/games/<id>/ + controller/src/games/registry.ts lazy entry (controller)
